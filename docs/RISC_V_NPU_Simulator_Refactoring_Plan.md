# RISC-V NPU Simulator Refactoring Plan (PRD + TDD, Incremental Evolution)
**기존 자산을 보존하는 Spec-Driven + Test-Driven 단계적 리팩토링 계획**

---

## 1. 목적 (Objective)
- 현재 ELF 기반 파이프라인(ELF → AdaptiveSimulator → CPU/NPU/Memory)을 유지하며 구조적 결함을 해소하고 확장 여지를 마련한다.
- 이벤트 엔진, 정확도 가드, 버스/메모리 모델 등 검증된 모듈을 재활용하면서 스케줄링·관측 지표·구성 관리 기능을 강화한다.
- 향후 CQ 기반 워크로드 지원과 고급 스케줄링을 도입할 수 있도록 **점진적 계층 추가** 및 **하위 호환 유지**를 전제로 설계를 정비한다.

---

## 2. 요구사항 (Requirements)
- **하위 호환성**: 기존 CLI(`python -m src.simulator.cli simulate …`), JSON 설정, 테스트 스위트가 항상 동작해야 한다.
- **점진적 확장성**: 새로운 ISA/CQ 계층은 선택적 모듈로 추가하고, 기본 경로(ELF 실행)는 최소 변경만 거친다.
- **모듈 재사용**: `memory.py`, `accuracy.py`, `npu/cluster.py` 등 현행 구현은 개선을 통한 고도화를 우선하며, 중복 파일 생성을 피한다.
- **테스트 주도**: 각 단계는 단위/통합 테스트와 벤치마크를 갱신하며, 기존 회귀 테스트를 유지한다.
- **관측 가능성**: 기존 수집 지표를 확대하되 구조체/JSON 포맷 변경 시 호환 계층 또는 마이그레이션 지침을 제공한다.

---

## 3. 범위 (Scope)
1. **베이스라인 정비**: 코드 베이스 구조, 모듈 경계, 로깅, 문서를 정리해 현재 상태를 명확히 한다.
2. **설정/CLI 개선**: JSON 설정 스키마를 보강하고, 옵션 확장(예: 스케줄 정책, 로깅)을 위해 검증기를 강화한다. 필요 시 YAML 로더는 JSON 출력으로 변환하는 어댑터로 제공한다.
3. **스케줄러/리소스 모델 강화**: `NPUCluster`와 이벤트 엔진을 확장하여 추가 정책(RR, 우선순위 등)과 지표를 단계적으로 도입한다.
4. **선택적 CQ 입력 계층**: IR/CQ 파이프라인은 별도 모듈로 추가하되, 기본 실행 경로와 독립적으로 실험할 수 있게 구성한다.
5. **검증 및 문서화**: 테스트, 벤치마크, 정확도 가드를 업데이트하고, 변경 사항을 문서화 및 튜토리얼에 반영한다.

---

## 4. 성공 기준 (Success Criteria)
- 기존 통합/단위 테스트 (`pytest`)와 벤치마크(`python -m src.simulator.cli benchmark …`)가 리팩토링 이후에도 통과한다.
- `AdaptiveSimulator` 기반 실행 경로가 유지되면서 추가된 매개변수(스케줄 정책, 모니터링 등)가 JSON 설정으로 제어 가능하다.
- NPU 스케줄러 확장(예: RR, 우선순위)이 기능 플래그나 설정으로 활성화되며, 회귀 지표(대기/스루풋/점유) 보고가 가능하다.
- 선택적 CQ 입출력 프로토타입이 통합 테스트에서 ELF 대비 ±15% 이내 성능 편차를 증명하거나 명확한 보정 계획을 제시한다.
- 문서(`docs/`, `specs/`)가 최신 구조와 설정/테스트 절차를 반영하고, 개발자는 새로운 경로를 단계별로 이해할 수 있다.

---

## 5. 시스템 구조 (현행 + 확장 계층)
```
[CLI (simulate/benchmark)]
        |
   JSON Config  ------------------------------+
        |                                     |
        v                                     v
[AdaptiveSimulator]                  [CQ Adapter (optional)]
        |                                     |
        |                    [CQ Reader/Validator -> Scheduler Bridge]
        +----[RISCVEngine]--------------------+
        |
        +----[MemorySystem (L1/L2/Bus/DRAM)]
        |
        +----[NPUCluster Scheduler]
              |-- DMA/Bus 연동
              |-- Metric Export
```
- **기본 경로**: ELF 로딩 → CPU/NPU/메모리 동시 시뮬레이션.
- **선택 경로**: 향후 CQ 입력이 필요할 때 JSONL 파서를 통해 `AdaptiveSimulator`에 작업을 삽입하되, 동일 리소스 모델을 재사용한다.
- 모든 구성 요소는 JSON 설정과 기존 이벤트 엔진(`EventScheduler`)을 기반으로 동작하며, 확장은 설정 플래그 또는 별도 모듈로 격리한다.

## 6. 단계별 로드맵 (Stage Plan)
### Stage 0 — 베이스라인 고정 & 가드레일
- [x] 코드/테스트/문서 현황을 정리하고 의존성 목록 업데이트.

- [x] 린터/포매터 설정(`black`, `ruff`) 확인.

- [x] CLI 플래그(`--scheduler-policy`, `--trace-components`) 확장과 로그/요약 구조 업데이트.

### Stage 2 — NPU 스케줄러 및 이벤트 엔진 개선
- [x] `NPUCluster` 리팩토링: RR/우선순위 정책, 지표 수집(대기/점유) 강화.

- [x] 단위 테스트 보강 및 시나리오 기반 통합 테스트(`tests/integration`) 추가.

### Stage 3 — 메모리/버스 모델 정밀화
- [x] 기존 `memory.py` 개선(로깅, 파라미터화, 통계 포맷 향상).
- [x] DRAM/버스 설정을 JSON 스키마와 연동.
- [x] 성능 테스트(`tests/performance`)로 회귀 검증.

### Stage 4 — 선택적 CQ 입력 계층 도입
- [ ] `CQ` 디렉터리 신설: JSONL 스키마, Reader/Writer, 검증 도구.

- [ ] CLI에 실험적 `run-cq` 서브커맨드를 추가하되, 기본 경로와 분리(Feature flag).
- [ ] CQ 경로 통합 테스트 및 ELF 대비 비교 벤치마크 작성.

### Stage 5 — 검증/문서 업데이트

- [ ] PRD/TDD 문서, 튜토리얼, 참조 설정을 최신화.
- [ ] 변경 사항 회고 및 추후 로드맵(예: WFQ/EDF, Dynamic Batching) 정의.

## 7. 검증 및 보정 전략 (Validation & Calibration)
- **회귀 테스트**: 기존 ELF 시나리오 테스트를 유지하고, 스케줄 정책별 시나리오를 추가한다.
- **벤치마크**: `python -m src.simulator.cli benchmark`로 기본 성능 범위를 측정하고, 스케줄러 변경 시 편차를 기록한다.
- **정확도 가드**: 주요 지표(CPU/NPU 점유율, 대기 시간, P90/P99 latency 등)를 골든 JSON에 추가하여 변화 감지.
- **Calibration**: DRAM/버스/스케줄러 파라미터 튜닝 시 단위 테스트 + 소규모 워크로드를 활용한 단계적 보정.

---

## 8. 설정 및 파라미터 관리
- 기본 포맷은 JSON을 유지하며, 새로운 필드는 `validate_simulator_config`에 추가한다.
- YAML 등 다른 포맷 지원 시, 내부적으로 JSON으로 변환하는 어댑터를 제공해 파이프라인 일관성을 유지한다.
- 스케줄러 정책, 로깅, NPU 파라미터는 설정 파일과 CLI 모두에서 제어 가능해야 한다.

---

## 9. 문서화 & 지원 자산
- `docs/`에 베이스라인 아키텍처 요약, 설정 예시, CQ 실험 절차를 단계별로 정리한다.
- `specs/`에는 스케줄 정책 정의, CQ 스키마 명세, 테스트 플랜을 기록한다.
- 튜토리얼/노트북은 기존 ELF 경로, 고급 스케줄 정책, CQ 실험 모드를 각각 소개한다.

---

## 10. 결론
- 본 계획은 기존 ELF 기반 시뮬레이터를 유지하면서, 설정/스케줄링/관측/테스트 체계를 강화하기 위한 **단계적 리팩토링 로드맵**이다.
- 선택적 CQ 입력과 고급 스케줄링은 별도 모듈로 도입하여 위험을 통제하며, 모든 변화는 JSON 설정과 기존 테스트를 기반으로 회귀를 보장한다.
- 각 단계 완료 후 회고를 통해 다음 확장 범위를 재평가하고, 필요한 경우 추가 로드맵(예: 동적 배칭, KV-Cache 관리)을 후속 문서로 정의한다.
